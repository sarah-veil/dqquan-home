# dqquan.com（半亩方塘）架构方案

日期：2026-10-24　｜　基于线上站点 + 本地仓库 `~/CodexProjects/dqquan_home` 实测

---

## 0. 一句话判断

**这个站的本体不是"页面"，是两个正在生长的序列——100 期书、按国家收拢的影像。**
所以架构不必再改视觉，要解决的是「序列长到 100 期 / 20 国 / 上千张照片时，结构会不会塌」。

现状是：**内容在，读者到不了**。31 期文章全写好了，搜索引擎只收录 2 个页面；4 国照片只有 12 张缩略图，点不进去；分享到微信没有卡片。

## 2. 三个结构性缺陷（必须修，越晚改代价越大）

### 缺陷一：URL 编号不补零，100 期必乱
现在 `books/01.html` … `books/31.html`。第 100 期是 `100.html`，字典序落在 `10.html` 和 `11.html` 之间，目录、上一期/下一期、sitemap 全错位。

**改法**：统一成三位目录 + 尾斜杠 —— `/books/031/`（每期一个 `index.html`）。
- 旧链接 `books/31.html` 不能断——GitHub Pages 不支持 301，用**兼容页**占位（旧 URL 里放 `<meta http-equiv="refresh">` + `rel=canonical` 指向新地址）。
- 好处：以后 `/books/031/` 下还能放配图、音频、附注，不再挤在根目录。

### 缺陷二：影像有索引没相册，等于没展示
现在点"2026 · 秘鲁"没有任何页面可去。老爷拍的是野生动物和风光，缩略图三张小图承载不了。

**改法**：每国一个相册页 `/photos/peru-2026/`，12–20 张大图纵向流或双列，点击原图。相册页要有：国家+年份、一句地理/叙事引子、照片序列、上一国/下一国。

### 缺陷三：只对内生长，不对外可达
31 期内容 + 4 国影像，搜索引擎只认 2 个 URL；分享出去没摘要卡片。等于写了一本书，只印了封面。

**改法**：全量 sitemap + 每页 OG 卡片 + JSON-LD。

## 4. 页面结构与模块

### 4.1 首页（保持现有结构，只补两处）
1. 页头：`半亩方塘` + `SEMI MUTA` + 导航三词
2. Hero：一句自述（老爷原文，不改）+ 竖幅照片 4:5
3. **阅读**：最新 3 期（期号 / 书名 / 一句提要 / 读这一期）
4. **记录**：最新一国（3 帧 + 全部国家影像）
5. 页脚：RSS / 邮箱

补：
- 每张卡片加 `<meta>` 之外的结构化链接（canonical）
- 首页 `<head>` 加 OG：`og:title=半亩方塘`、`og:description=阅读、思考，也拍一些照片`、`og:image=首图`、`og:type=website`

### 4.2 单期页（已有，需补三块）
现结构：期号 → 书名 → 一句提要 → 正文。
补：
- **正文宽度收窄**到 `max-width: 34em`（现在跟首页同宽，长文阅读偏累）
- **上一期 / 下一期**（底部，克制的一行）
- **本篇 OG**：`og:type=article`，`og:image` 用该期配图（`figs/` 里已有）

### 4.3 目录页（已有，需加分组）
现在 31 条平铺。加十期一段的分组标题（01–10 / 11–20 / 21–30 …），未发布期用浅色占位，形成"100 期进度感"。

### 4.4 国家相册页（新建）
1. 国家名 + 年份（大标题）
2. 一句引子（如"从太平洋岸到高原湿地"）
3. 照片流：桌面双列 / 手机单列，图注在下方小字
4. 上一国 · 下一国
5. OG：`og:type=article`，`og:image` 用该国第一张

### 4.5 关于页（新建）
1. 自述（**必须老爷原文，我只排版不代笔**）
2. 为什么读 / 为什么拍（各两三句）
3. 联系方式：邮箱（Cloudflare 已做保护）
4. 订阅：RSS 地址
5. 不做：社交账号墙、访客统计、留言板

### 4.6 404 页（新建）
一句话 + 回首页 / 去读书 / 去看照片三个入口。风格与全站一致。

## 5. 排版与视觉规范（延续 A 版，只增不动）

现有 token 已定稿，**原样保留**：

```
--paper  #fbfaf7   宣纸底
--ink    #1f1f1f   正文
--ink-2  #555555   次要
--ink-3  #6e6a62   三级/注释
--line   #e3e0d8   分隔线
--seal   #a63a2c   朱红（印章/链接/强调）
```

字体：`Songti SC / Noto Serif CJK SC / Source Han Serif SC / STSong, serif`
正文 `16px / line-height 1.95 / letter-spacing .01em`
标题 `clamp(30px, 4.2vw, 52px)`，字距 `.34em`
导航 `13px`，字距 `.2em`，hover 转朱红
容器 `max-width 1080px`，段落间距 `66px`，分隔线 1px

**新增三条规范**：
1. **单期正文区**：`max-width 34em`（约 620px 中文 30 字/行，最长可读区间）
2. **图片**：统一 `srcset`（800w / 1600w），WebP 优先，JPEG 兜底；`loading="lazy"` 除首屏第一张
3. **图注**：`12px / var(--ink-3) / letter-spacing .06em`，放在图下 10px

**不动**：纸本底色、宋体、印章、大留白、去饱和（`grayscale .15`）。这套语言是老爷迭代 14 次定下来的，方案不碰。

## 6. 内容规划

### 6.1 书：31 / 100
- 剩余 69 期。节奏建议**固定每周一期**（≈16 个月走完），双周则 32 个月太长。
- 每期固定四件套：`期号 + 书名 + 一句提要 + 札记正文`（现在已具备），建议再加**一句原文摘录**作为引文块，增强"可摘引性"。
- 目录要显示进度（xx/100），让读者看见这件事在往前推。

### 6.2 影像：4 国 / 现有 12 张
- 目标：每国 12–20 张成组。现有素材足够（小B `/photo/02-泉森摄影/` 下有秘鲁、挪威等合集）。
- 排序原则：**按地点的叙事顺序**，不按拍摄时间。
- 每国一句引子（现在已有，写得好，保持这个调子）。

### 6.3 不新增的内容类型
- 银行工作思考 → 不上公开站
- 家庭/私人信件 → 不上
- 音频朗读 → 已删（提交记录 `91d7fa6`），不复活

## 7. 技术与自动化

**保持纯静态 + GitHub Pages，不引入框架。** 理由：加载快、零维护、老爷不需要管服务器；这个体量 Next/Nuxt 纯属找麻烦。

### 7.1 生成管线升级
现在 `gen_books.py` 只生成目录 + RSS。扩成 `gen_site.py`，一次产出：

```
src/NN.md + 知识库台账/排期
        ↓
   gen_site.py
        ↓
books/NNN/index.html   （含上一期/下一期、OG、JSON-LD）
books/index.html       （分组目录 + 进度 xx/100）
sitemap.xml            （全量：首页 + 32 书页 + photos + 4 相册 + about）
feed.xml               （已有逻辑复用）
```

单个脚本、幂等、跑完直接 `git commit && push`。

### 7.2 SEO / 分享补全
- `sitemap.xml`：从 2 条 → 40+ 条，每页带 `lastmod`
- OG 卡片：每页必有 `og:title / og:description / og:image(1200×630) / og:url / og:type`
- JSON-LD：书页 `Article`（`headline`+`datePublished`+`author`），相册 `ImageGallery`
- `robots.txt` 保留 Cloudflare 的内容信号段（现在那份是 CF 自动加的，别删）

### 7.3 图片
- 现有 12 张 → WebP（505KB → 约 150KB），保留 JPEG 兜底
- 相册页懒加载
- 新增照片走同一套处理脚本（`make_images.py`，输入原图 → 输出 800w/1600w 两档 WebP）

### 7.4 站内搜索（三期再说）
31 期不需要。到 60 期左右用 `minisearch` + 一个 `books.json` 索引（<20KB），纯前端，零后端。
